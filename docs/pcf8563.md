# PCF8563 integration

The production driver is lib/rtc/pcf8563.hpp/.cpp and uses the NXP PCF8563 data sheet as register authority.

## Electrical setup

Address is 0x51. SDA=GPIO8 and SCL=GPIO9. There are intentionally no always-powered external I2C pull-ups; firmware selects INPUT_PULLUP before starting Wire at 100 kHz and uses a 50 ms bus timeout.

## Registers and semantics

Control_status_1 is 00h. Control_status_2 is 01h: bit4 TI_TP, bit3 AF, bit2 TF, bit1 AIE, bit0 TIE. TI_TP=0 selects level behavior. AF/TF writes are logical-AND: writing zero clears that flag and writing one preserves it. Read-modify-write helpers explicitly preserve the other flag.

Time registers 02h–08h are BCD. Seconds bit7 is VL and makes time untrusted. The driver reports VALID, INVALID_VL, UNINITIALIZED, or I2C_ERROR and never exports invalid calendar bytes as UTC.

Alarm registers 09h–0Ch provide minute, hour, day, and weekday only. Timer control 0Eh selects 4096 Hz, 64 Hz, 1 Hz, or 1/60 Hz; timer value is 0Fh.

Every critical timer/alarm/time write has readback validation. The final release helper can atomically clear selected flags and disable AIE for a completed one-shot alarm.

## Scheduling policy

UTC is stored in the RTC. A trusted Gateway ACK sets the clock when invalid or when absolute drift exceeds five seconds. The last successful sync is persisted.

A one-shot maintenance target is accepted only if minute-aligned, 60 seconds to 27 days in the future, and representable in years 2000–2099. Minute/hour/day are programmed, weekday is disabled, and the full UTC target stays in NVS. AF wake is accepted only when valid RTC time matches that target within five minutes; this prevents recurring month/year ambiguity from silently becoming maintenance.
